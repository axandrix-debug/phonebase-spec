# Design: storage

- Побайтовая раскладка записи журнала:
  `op(1Б) | seq(8Б) | id(8Б) | len_name(2Б) | name(UTF-8) | len_phone(2Б) |
  phone(UTF-8) | crc32(4Б)`; CRC32 считается по всем байтам записи до поля
  crc [[Python-zlib]]. Коды операций: ADD=1, UPDATE_NAME=2, UPDATE_PHONE=3,
  DELETE=4.
- Семантика полей по кодам операций: ADD — name и phone новые; UPDATE_NAME —
  name новое, phone пусто; UPDATE_PHONE — phone новое, name пусто; DELETE —
  оба поля пусты.
- Заголовок снапшота: `applied_seq(8Б) | next_id(8Б) | count(8Б) | crc32(4Б)`
  + записи; контрольные суммы заголовка и данных.
- Порядок восстановления: OS-блокировка → снапшот (если валиден) → хвост
  журнала (`seq > applied_seq`, CRC каждой записи, ресинхронизация при
  повреждении) → построение индексов;
  `next_id = max(снапшот.next_id, max id в хвосте журнала)`.
- Append-only + fsync — по модели атомарного коммита SQLite [[SQLite-atomic]].
  На Windows `os.fsync` = FlushFileBuffers, атомарная замена файла —
  `os.replace` [[Python-os]].
- Ресинхронизация после повреждённой записи: побайтовое сканирование вперёд
  до первой позиции, где разбирается запись с валидной CRC (длины полей
  закодированы в самой записи, ложные срабатывания маловероятны).
- Намеренно отсутствует: многооперационные транзакции, параллельные писатели,
  репликация, шифрование — вне рамок [ADR-5]; каждое расширение — новый ADR.
