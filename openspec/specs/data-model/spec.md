# Capability: data-model

## Requirements

### Requirement: Запись
Система SHALL хранить данные как записи `(id: int, name: str, phone: str)`:
`name` — отображаемая форма имени, `phone` — каноническая форма телефона.
ID назначается системой, монотонно растёт и не переиспользуется после
удаления [ADR-1]. Значение счётчика ID переживает рестарт и компактификацию
(см. `specs/storage/`: `next_id` в снапшоте + max id в хвосте журнала).

#### Scenario: ID не переиспользуются после рестарта
- **GIVEN** добавлены записи, запись с максимальным id удалена, выполнена
  компактификация, БД закрыта и открыта вновь
- **WHEN** добавляется новая запись
- **THEN** её id больше любого ранее выданного

### Requirement: Канонизация телефона
Система SHALL приводить телефон к канонической форме до любого сохранения или
сравнения [ADR-3]. «Цифры» = ASCII 0–9; иные числительные (включая
полноширинные) цифрами не считаются:
1. Оставить только цифры; зафиксировать наличие ведущего «+».
2. Если был ведущий «+» — каноническая форма: `+` + цифры (любое количество).
3. Если «+» не было и ровно 11 цифр с первой «8» — форма `+7` + остальные 10.
4. Если «+» не было и ровно 11 цифр с первой «7» — форма `+7` + остальные 10.
5. Если «+» не было и ровно 10 цифр — форма `+7` + все 10 [ADR-10].
6. Во всех остальных случаях — цифры как есть.

Правила 3–5 — допущение о российском плане нумерации, подтверждено
владельцем продукта (2026-10-28) [ADR-3, ADR-10].

Таблица примеров — одновременно база параметризованных тестов:

| Ввод | Каноническая форма |
|---|---|
| `+7 (921) 123-45-67` | `+79211234567` |
| `8 921 123 45 67` | `+79211234567` |
| `89211234567` | `+79211234567` |
| `9211234567` | `+79211234567` |
| `812 345-67-89` | `+78123456789` |
| `+44 20 7946 0000` | `+442079460000` |
| `+39 012 345 678` | `+39012345678` |
| `39012345678` | `39012345678` |
| `８9211234567` (полноширинная «８») | ошибка: нет ASCII-цифр |
| `02` | ошибка: меньше 3 цифр |
| `abc` | ошибка: нет цифр |

### Requirement: Валидация телефона
Система SHALL отклонять телефон (ValidationError), если после очистки
ASCII-цифр меньше 3 или больше 15. Верхняя граница следует E.164 [[E.164]];
нижняя отсекает вырожденные ключи, допуская короткие внутренние номера.

#### Scenario: невалидный телефон
- **WHEN** вводят телефон `02` или `abc`
- **THEN** ValidationError, запись не создаётся

### Requirement: Канонизация имени
Система SHALL нормализовать имя: убрать крайние пробелы, внутренние
последовательности пробельных символов (любые Unicode-whitespace) заменить
одним пробелом. Ключ поиска `name_key` = нормализованное имя через casefold
[[Python-casefold]]; отображаемая форма хранит исходный регистр.

#### Scenario: регистр не влияет на поиск
- **WHEN** сохранено имя «Иван Петров» и ищут «ИВАН ПЕТРОВ»
- **THEN** запись найдена

### Requirement: Уникальность пары
Система SHALL гарантировать уникальность пары `(name_key, канонический phone)`
в пределах БД [ADR-6]. При обновлении записи проверка уникальности исключает
саму обновляемую запись.

#### Scenario: дубликат при добавлении отклоняется
- **GIVEN** сохранена пара («Иван Петров», «+79211234567»)
- **WHEN** добавляют («ИВАН ПЕТРОВ», «8 (921) 123-45-67»)
- **THEN** DuplicateError; в базе остаётся ровно одна такая запись

#### Scenario: обновление записи её же значением не конфликтует
- **GIVEN** запись («Иван Петров», «+79211234567»)
- **WHEN** у этой же записи меняют имя на «ИВАН ПЕТРОВ» (тот же name_key)
- **THEN** операция успешна; DuplicateError не возникает

### Requirement: Инварианты записи
Система SHALL поддерживать на каждой операции инварианты:
I1 — имя 1–100 символов после нормализации (верхняя граница — практический
лимит, защищает журнал от вырожденного ввода); I2 — телефон каноничен и
валиден; I3 — уникальность пары; I4 — уникальность и монотонность id.

#### Scenario: пустое имя отклоняется
- **WHEN** добавляют запись с именем из одних пробелов
- **THEN** ValidationError (нарушен I1)

#### Scenario: имя длиннее 100 символов отклоняется
- **WHEN** добавляют запись с именем 101 символ после нормализации
- **THEN** ValidationError (нарушен I1)
