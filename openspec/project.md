# PhoneBase — проектный контекст

## Назначение

Однопользовательская телефонная база: хранит пары «Имя — Телефон», ищет имена
по телефону и телефоны по имени, переживает сбои без потери подтверждённых
данных. Визуальный UI + программный API. С нуля на Python 3.12+, только
стандартная библиотека [[ТЗ]] [ADR-4].

## Пользователи

Оператор справочной приёмной/офиса — единственный локальный пользователь;
пять ролей по намерениям — см. `README.md`, CUJ-1…CUJ-5 (поиск по телефону,
добавление, редактирование, удаление, обзор).

## Единый язык (глоссарий)

| Термин | Значение |
|---|---|
| Запись | Пара «Имя + Телефон» с уникальным id; атомарная единица хранения [ADR-1] |
| ID | Целое ≥ 1; монотонно растёт; не переиспользуется после удаления |
| Каноническая форма | Единый вид значения, по которому записи сравниваются и ищутся [ADR-3] |
| name_key | Ключ имени: нормализованные пробелы + casefold [[Python-casefold]] |
| Журнал | Append-only файл операций; единственный источник истины [ADR-2] |
| Снапшот | Полная копия состояния на момент N; активируется атомарным rename |
| Подтверждённая операция | Записана в журнал и сброшена на диск (fsync); только тогда API вернул успех |
| Поиск | По имени — префикс по name_key [ADR-9]; по телефону — точное совпадение канонической формы [ADR-9] |

## Границы (bounded contexts) и правила зависимостей

```
GUI (specs/gui) → API (specs/api) → Ядро (specs/storage, specs/data-model)
```

- GUI не обращается к ядру и файлам напрямую — нарушение = архитектурная ошибка.
- API — единственная точка валидации и канонизации входа.
- Ядро не знает о GUI и о том, как пользователь вводил значения.

## Формат требований

- Требование: `### Requirement: …`, поведение через SHALL.
- Сценарий: `#### Scenario: …`, шаги `- **GIVEN** / **WHEN** / **THEN** / **AND**`.
- Каждое содержательное утверждение снабжено ссылкой `[[Ключ]]` (внешний
  источник, расшифровка ниже) или `[ADR-N]` (внутреннее решение) — бездоказательных
  утверждений в спеке нет [[Урок]] стр. 44.
