# REVIEW — ревью спецификации «золотыми рыбками»

Методика: Elephant + Goldfish [[Урок]] стр. 41–45. Четыре субагента-«рыбки»
запущены с пустым контекстом; каждая получила один изолированный вопрос,
список файлов спеки и текст ТЗ — и ничего из контекста «слона». Каждая находка
обязана была иметь два доказательства: теоретическое (рассуждение по тексту)
и практическое (проверяемое действие). Спорные находки переданы агенту-критику
(тоже пустой контекст, полное ТЗ с уточнением автора).

## Отчёты рыбок

**Рыбка № 1 «Лишнее»** — 13 находок (1 high, 4 medium, 8 low).
Ключевые: валидация телефона «противоречит букве ТЗ» (high); мёртвые
`count()`/`iter_all()`; дублирующий бюджет 200 мс в gui; update/delete и
запрет дублей «не из ТЗ»; фантомная ссылка на «таблицу примеров»; дублирование
правила границ в четырёх файлах. Проверено и НЕ признано лишним: канонизация,
CRC32 и обработка битого хвоста, lock, бюджеты performance, ADR-4, ADR-7.

**Рыбка № 2 «Недостающее»** — 18 находок (5 high, 7 medium, 6 low).
Ключевые: stale lock после kill блокирует durability-сценарий; не определён
механизм привязки снапшота к позиции журнала и поведение при краше между
rename и обрезкой; «повреждённый снапшот не фатален» невыполнимо после
компактификации; счётчик ID ломается после компактификации; канонизация не
определена для 11 цифр с первой ∉ {7, 8}; self-конфликт уникальности при
update; семантика полей журнала для UPDATE/DELETE; валидность поискового
запроса; частичный отказ при редактировании двух полей.

**Рыбка № 3 «Спорные решения»** — 12 позиций (3 high, 4 medium, 5 low).
Ключевые: противоречие «снапшот + обрезка журнала» ↔ «повреждённый снапшот
не фатален»; lock-файл после kill; 10-значные номера не унифицируются с
«+79…»; обрезка по CRC в середине журнала теряет подтверждённые операции;
точный поиск воспринимается пользователем как «сломанный»; стоимость
компактификации не бюджетирована. Не спорными признаны: ADR-3 (потеря
исходного написания), ADR-6, выбор исключений вместо Result-типов.

**Рыбка № 4 «Производительность»** — вердикт: цифры реалистичны (поиск —
запас ~3 порядка; старт — запас 4–10x; fsync на NVMe — запас до 10x), но
проверяемость неполна. Ключевые: компактификация — небюджетированный пик;
kill-тест проверяет атомарность, а не durability против потери питания
(page cache переживает kill) — нужен corruption-fuzz; целевая конфигурация
невоспроизводима без фиксации окружения; методика p95/p99 неполна (выборка,
прогрев, GC); загрузка fixture через API ≈ 17 минут — нужен bulk-путь.

## Вердикты критика по спорным находкам

| # | Находка | Вердикт | Решение |
|---|---|---|---|
| D1 | Валидация телефона «противоречит ТЗ» | мнимация | Отставить: «Телефоны» в ТЗ — уже критерий; границы заземлены [[E.164]] |
| D2 | update/delete + CUJ-3/4 «не из ТЗ» | мнимация | Отставить: книжка без правки/удаления нефункциональна; CUJ — черновик по плану, владелец подтверждает |
| D3 | Запрет дублей (ADR-6) «из интуиции» | мнимация | Отставить: решение задокументировано, видно владельцу через CUJ-2 |
| D4 | `count()`/`iter_all()` — мёртвый API | мелочь | Правка: сценарий «сверка после восстановления» в api/spec.md — методы привязаны к crash-тесту |
| D5 | Запрет sqlite3 «противоречит stdlib» | мнимация | Отставить: полное ТЗ — «готовую СУБД использовать не предполагается»; цитата зафиксирована в project.md |
| D6 | Точный поиск (ADR-7) спорен | мнимация | Отставить: ограничение уже вынесено владельцу; исправлена ссылка CUJ-1 → CUJ-3 |
| D7 | 10-значные номера не унифицируются с «+7/8» | мелочь | Правка: явное «Последствие» в ADR-3 + вопрос в комплект подтверждения владельцем; поведение не менять |
| D8 | fsync на каждой операции + 10 мс p95 машино-зависимы | мнимация | Отставить: машино-зависимость объявлена контрактом (целевая конфигурация); микробенчмарк fsync — первая задача tasks.md |

Общий вывод критика: блокирующих утверждению находок нет; спека принимается
с оговорками — главное условие: ручное подтверждение владельцем CUJ-1…CUJ-4
и двух ограничений поиска (ADR-7, ADR-3).

## Применённые правки (по бесспорным сходящимся находкам)

1. **Компактификация и восстановление** (рыбки 2, 3, 4 — сходятся): в
   storage введены `seq` у записей журнала и `applied_seq`/`next_id` в
   снапшоте; replay идемпотентен (краш между rename и обрезкой безопасен);
   формат снапшота и его контрольная сумма определены; fsync временного
   файла до rename. Компактификация перенесена на открытие/закрытие — пик
   задержки выведен из интерактива; порог — константа.
2. **Блокировка** (рыбки 2, 3, 4): OS-файловая блокировка, автоматически
   снимаемая при смерти процесса; сценарий «повторное открытие после kill».
3. **Повреждение в середине журнала** (рыбки 2, 3): вместо молчаливой обрезки —
   ресинхронизация с восстановлением подтверждённых операций после точки
   повреждения; сценарий на середину журнала.
4. **Счётчик ID** (рыбка 2): `next_id` в снапшоте + max id в хвосте журнала;
   сценарий «ID не переиспользуются после рестарта с компактификацией».
5. **Канонизация телефона** (рыбки 1, 2, 3): закрыт пробел «11 цифр,
   первая ∉ {7,8}» (правило «иначе — цифры как есть»); «цифры» = ASCII 0–9;
   восстановлена таблица примеров (10 строк, включая полноширинную «８» и
   «+39…») — она же база параметризованных тестов; фантомные ссылки в
   design.md/tasks.md стали валидными.
6. **API** (рыбка 2 + критик D4): уникальность при update исключает саму
   запись (+сценарий); поисковый запрос канонизируется без валидации —
   пустой список вместо ошибки; порядок `iter_all()` — по id; семантика
   открытия path; сценарий «сверка после восстановления».
7. **GUI** (рыбки 1, 2, 4): убран дублирующий бюджет 200 мс (теперь одна
   строка в performance с методикой замера); ошибки старта — диалог, не
   трейсбек; кнопки без выделения недоступны; таблица перечитывается после
   мутаций; частичный отказ при двухполевом редактировании отображается
   честно; пустой запрос — подсказка без обращения к API.
8. **Performance** (рыбка 4): kill-тест переименован по смыслу (атомарность),
   durability проверяется corruption-fuzz; зафиксирована целевая конфигурация
   (Windows 10+, NTFS, SSD, Python 3.12.x) и печать окружения в отчёте;
   методика: ≥10 000 замеров, nearest-rank, прогрев, gc, seed, исключение
   ошибок из замеров; bulk-fixture; бюджет закрытия с компактификацией ≤ 2 с;
   обоснование асимметрии p95/p99; контроль памяти через tracemalloc.
9. **Гигиена** (рыбка 1): побайтовая раскладка журнала переехала из spec.md в
   design.md; правило границ нормативно живёт только в project.md (в gui/api —
   ссылки); убраны «v2-фразы» из api/design.md; «настраиваемость» компактификации
   заменена константой; в [[ТЗ]] процитировано уточнение о запрете готовой СУБД;
   добавлен источник [[Python-os]].
