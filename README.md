# PhoneBase — телефонная база данных (учебный проект, Урок 3)

Однопользовательская база данных «телефонная книжка» на Python 3.12+ (только stdlib):
хранит пары «Имя — Телефон», двунаправленный поиск, GUI + программный API.
**Статус: только спецификация, код не пишется** [[ТЗ]].

## Базовые пользовательские пути (CUJ)

Подтверждены владельцем продукта 2026-10-28. Пользователь — оператор
справочной приёмной/офиса. Владелец подтвердил контекст, префиксный поиск
по имени [ADR-9], унификацию 10-значных номеров [ADR-10] и обзор книжки
(CUJ-5).

**CUJ-1. «Кто звонил?» — поиск по телефону.**
Пользователь: оператор/секретарь, увидел входящий или пропущенный номер.
Намерение: понять, чей это номер.
Путь: открыл приложение → выбрал направление «По телефону» → ввёл номер так,
как он высвечивается на телефоне (любое форматирование) → «Найти» → увидел
имя (имена) владельца номера.
Результат: имя определено за секунды; если номера нет — понятное
«Ничего не найдено», а не пустая таблица.

**CUJ-2. «Записать контакт» — добавление.**
Намерение: сохранить нового клиента или партнёра.
Путь: открыл приложение → «Добавить» → ввёл имя и телефон → сохранил.
Результат: запись переживает закрытие приложения и сбой питания; находится
поиском в обе стороны; если такая пара уже есть — понятное сообщение,
дубль не создаётся.

**CUJ-3. «Сменился номер» — редактирование.**
Намерение: актуализировать контакт.
Путь: нашёл человека по началу имени → выбрал запись → «Изменить» → ввёл
новый номер → сохранил.
Результат: телефон обновлён, имя не потеряно, поиск по старому номеру
запись больше не находит.

**CUJ-4. «Почистить базу» — удаление.**
Намерение: убрать ошибочную запись.
Путь: нашёл запись → «Удалить» → подтвердил выбор.
Результат: запись исчезла из поиска; случайное удаление предотвращено
диалогом подтверждения.

**CUJ-5. «Полистать книжку» — обзор.**
Намерение: освежить в памяти, кто есть в базе, без конкретного запроса.
Путь: открыл приложение → «Показать все» (или пустой запрос) → первые 500
записей в алфавитном порядке → при необходимости уточнил запрос.
Результат: обзор получен без знания имени; если записей больше 500,
подсказка предлагает уточнить запрос.

## Неочевидные связи (важно знать до чтения спеки)

- GUI не касается ядра хранения напрямую — только через программный API
  (правило границ, `openspec/project.md`).
- Журнал операций — единственный источник истины; снапшот — только ускорение
  старта (`openspec/specs/storage/`) [ADR-2].
- Канонизация выполняется один раз на границе API; без неё поиск
  «+7 (921) 123-45-67» не нашёл бы «89211234567» [ADR-3].
- «Хорошая база данных» и «много записей» из ТЗ операционализированы в
  измеримые бюджеты (`openspec/specs/performance/`) [ADR-8].

## Принятые решения

Все значимые решения фиксируются в `ADR.md` с номерами; ссылки в спеке имеют
вид [ADR-N]. Новое решение = новый номер; принятые записи не переписываются —
при пересмотре меняется статус и добавляется новый ADR. Действующие решения:

- [ADR-1] Модель данных: плоская запись «Имя + Телефон»
- [ADR-2] Хранение: append-only журнал + снапшоты
- [ADR-3] Канонизация телефонов и имён (допущение о российском плане
  нумерации подтверждено владельцем)
- [ADR-4] GUI: Tkinter, только стандартная библиотека
- [ADR-5] Однопользовательская, однопроцессная система
- [ADR-6] Запрет дубликатов пары (name_key, phone)
- [ADR-7] Только точный поиск — superseded, заменён ADR-9
- [ADR-8] Операционализация «хорошая» и «много» в измеримые бюджеты
- [ADR-9] Префиксный поиск по имени; точный — по телефону
- [ADR-10] 10-значные номера унифицируются с формой «+7…»
